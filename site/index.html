Two presentation systems

Select the package for the application model.

The WPF and MAUI implementations are deliberately separate. Each package exposes direct pixel storage through an API designed for its presentation stack.

01

Windows desktop

Tedd.WriteableBitmap

Backs a WPF InteropBitmap with an unmanaged memory section. Write through a span or pointer, invalidate the bitmap, and bind BitmapSource to an Image.

  • Byte, 16-bit, and 32-bit span access
  • Raw pointer and IntPtr access
  • Owned or borrowed memory sections
  • Stride-aware image loading
Open WPF package on NuGet ↗
02

Cross-platform UI

Tedd.WriteableBitmap.Maui

Provides a platform-native pixel swap chain and a dedicated SKGLView. A nonblocking write lease allows CPU frame production to overlap GPU presentation.

  • Allocation-free, stack-only write leases
  • Three native buffers by default
  • Coalesced UI-thread redraw requests
  • Nearest or linear sampling
Open MAUI package on NuGet ↗

Explicit data path

Memory remains under application control.

The library removes per-pixel presentation calls from the hot path. The application writes a complete frame in native storage and signals when presentation may proceed.

Graphics primitives

Low-level access with explicit contracts.

Dimensions, stride, color layout, ownership, and publication remain visible. The API does not conceal buffer semantics that affect correctness.

▦

Memory layout

Stride-aware addressing

Each bitmap reports the byte distance between adjacent rows. MAUI pixel indexing accounts for row padding.

</>

Typed direct access

Use byte, 16-bit, or 32-bit spans and pointers according to the selected pixel format.

⇄

Concurrent presentation

MAUI write leases prevent a producer from modifying buffers retained by Skia during presentation.

◇

Native color layout

MAUI uses the platform-native 32-bit Skia color type with premultiplied alpha.

⌁

No managed staging image

Frames remain in native bitmap storage; normal CPU-to-GPU upload still occurs during MAUI presentation.

⊞

Binding-ready output

WPF exposes BitmapSource. MAUI exposes a bindable WriteableBitmapView.

NuGet installation

Install one package.
Write one frame.

Select a package to view its installation command and minimum working pattern.

MAUI buffer contract: Write every pixel required by a new frame. A leased back buffer may contain an older frame.

dotnet add package Tedd.WriteableBitmap
WPF · MainWindow.xaml.cs
using System;
using System.Windows.Media;
using Tedd;

private readonly WriteableBitmap _bitmap = new(
    640, 360, PixelFormats.Bgra32);

private void RenderFrame()
{
    var pixels = _bitmap.ToSpanUInt32();
    pixels.Fill(WriteableBitmap.FromRgba(
        r: 8, g: 127, b: 120, a: 255));

    _bitmap.Invalidate();
    Preview.Source = _bitmap.BitmapSource;
}

protected override void OnClosed(EventArgs e)
{
    _bitmap.Dispose();
    base.OnClosed(e);
}
dotnet add package Tedd.WriteableBitmap.Maui
MAUI · frame producer
using Tedd.Maui;

if (!Bitmap.TryBeginWrite(out var write))
    return;

try
{
    var pixels = write.Pixels;
    pixels.Fill(WriteableBitmap.FromRgba(
        r: 8, g: 127, b: 120, a: 255));
}
finally
{
    write.Dispose(); // Publishes the frame.
}
