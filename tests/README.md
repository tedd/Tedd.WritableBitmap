# Unit tests and coverage

Run from the repository root on Windows, using the SDK selected by `global.json` and the .NET 10 and .NET 11 preview desktop runtimes. Both test projects execute against both framework versions:

```powershell
dotnet test src/Tedd.WriteableBitmap.sln --configuration Release --collect "XPlat Code Coverage" --settings tests/coverage.runsettings --results-directory artifacts/coverage --logger trx
./tests/Get-Coverage.ps1
```

Use a fresh results directory when comparing runs; the summary displays every report it finds. Pass `-ResultsDirectory <path>` to summarize another directory, and `-ShowUncovered` to list uncovered lines by class.

Individual projects can be run with `dotnet test tests/Tedd.WriteableBitmap.Wpf.Tests` or `dotnet test tests/Tedd.WriteableBitmap.Maui.Tests`. WPF tests execute bitmap operations on STA threads and use real Windows memory mappings and codecs. MAUI tests use real Skia pixel buffers and raster surfaces, with test handlers and dispatchers for the MAUI view lifecycle. Unit tests do not require a visible window or a GPU context.

Coverage includes both production assemblies, including properties; tests and third-party dependencies are outside the measurement. No production failure paths are excluded to raise the percentages. CI collects the same Cobertura reports and TRX test results as the local command and uploads them as `test-results-and-coverage`.

Coverage measures executed managed code, not native Windows/Skia internals or Android/iOS/Mac Catalyst GPU behavior. The separate `Tedd.WriteableBitmap.Maui.Compatibility` project checks that consumers compile on all supported MAUI targets. Device rendering still requires integration testing.

## Measured coverage

Release results on Windows with .NET 10 and .NET 11 Preview (2026-09-04). Counts are per runtime; all 580 test executions pass:

| Implementation | Passing cases | Lines | Branches |
| --- | ---: | ---: | ---: |
| WPF | 97 | 99/100 (99.00%) | 66/67 (98.51%) |
| MAUI | 193 | 436/466 (93.56%) | 165/196 (84.18%) |

MAUI layout, builder registration, and write leases have 100% line and branch coverage. The view has 98.48% line coverage. The MAUI totals include eight uncovered lines and twelve branches generated by the MAUI binding source generator; these are retained in the report.

The remaining WPF line handles native `CreateFileMapping` allocation failure. Remaining MAUI paths concern native allocation failures, unsupported platform pixel layouts, native-image creation failure, generation-counter wraparound, concurrent-disposal fallback checks, and defensive lifecycle states that cannot be reached through normal public calls. Tests do not exhaust process memory, corrupt private state, or exclude these paths to manufacture 100% coverage.

WPF regressions verify borrowed-handle ownership, explicit offsets, padded rows, packed-pixel stride calculation, complete clearing, BMP decoding, DPI-independent cropping, case-insensitive extension matching across cultures, and immediate input-file release. `GetIndex` retains its documented logical `y * Width + x` behavior; padded byte buffers must use `Stride` when computing row addresses.
